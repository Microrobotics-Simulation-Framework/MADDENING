# Tests allowed to exceed the default lane's time budget.

# Read by scripts/report_test_durations.py in CI (.github/workflows/ci.yml).
# One pytest node id per line, then " # " and the reason. The budget, from
# docs/developer_guide/testing_standards.md:
#
#   up to 1 s   fine
#   1-5 s       watch list; optimise when you are in the file
#   over 5 s    mark @pytest.mark.slow (still runs in slow-tests.yml:
#               scheduled 3x a week on main only; on a release branch
#               only when dispatched by hand), make it much faster, or
#               keep it here with "kept: <why it must run on every push>"
#
# An unlisted test over 5 s gets a warning on the run; over 20 s it fails the
# job. The 4x gap is runner noise: the same test varies 1.7x between runs at
# the median, 3x at the 90th percentile.
#
# Every entry is "kept: <why>". The tests that were already over 5 s when
# the gate arrived (2026-09-24) have all been marked slow, sped up, or kept
# that way; add an entry only with the reason the test must run on every push.
